# 用户交互卡片规范（必须遵守）

本 skill 通过 4 张卡片与用户交互。**卡片不是脚本产物，也不是某个客户端的 UI 组件**——
它是 AI 在执行工作流时，按本规范在当前对话里现渲染的交互层（文字 / 表格 / 可视化均可）。
因此无论运行在 WorkBuddy、dsh 还是其它 Agent 客户端，只要加载了本 skill，就必须按本规范在对应节点弹出卡片。

原则：卡片要让用户明确「这一步在干什么、要花多少钱、调什么模型、需要我确认什么」，
**不能只丢技术日志**。价格只报有据可查的数，未公开的如实标注，不编数字。

---

## 时机总览

| 卡片 | 触发时机 | 门控 |
|---|---|---|
| 1 需求确认卡 | Step 2 拆解完成后、进花钱步骤前 | 用户确认画幅 / VLM / 生成范围才继续 |
| 2 成本预估卡 | Step 4 生成提交前 | 用户确认预估才进入生成 |
| 3 镜头表卡 | Step 3 人工卡点（必须） | 用户确认逐镜方案才生成 |
| 4 成片交付卡 | Step 5 合成完成后 | 无（交付收尾） |

> 顺序说明：实际流程里「镜头表卡（Step 3）」在「成本预估卡（Step 4 前）」之前。
> 若先把估价并入镜头表卡逐镜展示，也可在 Step 3 一次弹「镜头表 + 合计估价」，
> 但 Step 4 提交前仍须有一次明确的花费确认。

## 输入方式与下载失败降级（Step 1 · 入口层说明）

remake 有**两种并列入口**，都汇入同一个 `source.mp4`，后续流程完全一致：

1. **发链接**（默认）：`fetch.py --job JOB --url "..."`，由 yt-dlp 自动下载。
2. **上传本地视频**：用户把视频文件放进对话/工作区后，`fetch.py --job JOB --local <path>`。
   - 上传文件只作临时输入，**分析完按「下载即删」红线删除**，不缓存、不分发源视频。
   - 用户自行下载/上传不改变合规义务：只用于本地临时 AI 分析，版权归用户，国内发布仍需做 AI 标注。
   - 平台下载的是重压缩源，本地原始文件离线拆解更准。

**下载失败时怎么提示用户**（嵌在 Step 1，不是一张独立卡片，但同样必须遵守）：

| 下载结果 | 给用户的提示 |
|---|---|
| `OK` | 正常继续，不提示 |
| **明确失败**（平台拒绝 / 解析报错 / 格式不支持） | 如实说「这条链接当前下载失败」，给出两种出路：① 换一条可访问的链接；② **自行下载后上传**——从 `config.json` 的 `download_helpers` 读取在线服务清单展示给用户（名称 + URL + note），让用户跳转下载再把文件传进来。**不盲目重复下载**。 |
| `STATUS_UNKNOWN`（超时 / 断网 / 还在跑） | 只说「状态未知，稍后自动再查」，**保留任务 ID**，**不提示重下、不提示重生成、不提示换服务**——原则：不确定就不重发。 |

**在线下载服务清单是可配置项**：只从 `config.json` 的 `download_helpers` 数组读取并展示，**不要在卡片或脚本里硬编码服务域名**。用户可随时增删/替换这个数组来换服务。清单仅为便利提示，skill 不背书任何站点的资质或可用性，展示时保留各条 `note` 里的风险说明（如广告、域名易变、YT 官方实例可能受限）。

## 卡片 1 · 需求确认卡

**何时弹**：贴链接、`fetch` + `decompose` 完成后，进入任何花钱步骤之前。

**必含字段**：
- 识别到的平台、视频时长、源分辨率、检测到的镜头数
- 拆解结论摘要：画面类型（AI 生成 / 代码渲染）、建议还原画幅（9:16 或 16:9）
- 将生成几镜、哪几镜走 `code_remake`（不花钱）
- 请用户确认三项：**目标画幅**（竖屏 9:16 / 16:9 还原）、**是否开 VLM**（重压缩源建议开，烧 chat token）、**生成范围**（全片 / 前 N 秒 / 指定镜）

**门控**：用户未确认前，不进入 VLM 复核、不进生成。

## 卡片 2 · 成本预估卡

**何时弹**：Step 4 生成提交前；若与镜头表卡合并，也须在提交前再次明确花费确认。

**必含字段**：
- 调用模型清单 + 各模型单价 + 按镜数 / 时长 / 分辨率算出的**预估总价**
- 明确区分：哪些单价是 PT 官方公开、哪些是「按实际消费 / 仪表盘为准」
- 估算方式说明：视频走 `pt_video.py estimate`（只估不扣费），音频 / VLM 按实际
- 醒目标注「**仅估算，以账单为准**」

**门控**：用户确认后才进入生成；预估不准要在卡上写明口径，不承诺固定价。

### 模型与价格口径（只报有据可查的价）

数据来源：`powertokens-kit/README.zh-CN.md` §5 定价表、§15 估算规则（PT 预扣单价，美元）。

| 步骤 | 用途 | 模型（默认） | 计费方式 | 单价 |
|---|---|---|---|---|
| Step 2 拆解 | VLM 逐镜复核 | `qwen3.8-flash`（PT chat） | 按 token | PT 未公开固定单价，按实际 token 扣费 |
| Step 4 生成 | 逐镜画面 | `wan3.0-video`（可换） | 视频预扣 | $0.20 / 5s·720p（官方表） |
| 音频 BGM | 文生音乐 | `audio1.0`（Vidu text2audio） | 按次 / 时长 | PT 未公开单价，以仪表盘为准 |
| 音频旁白 | TTS | `speech-2.8-turbo` | 按字符 / 次 | PT 未公开单价，以仪表盘为准 |
| 声音分离 | 本地 67MB 模型 | rea-video UVR / BandIt | 本地 | 免费（不调 PT） |

视频模型单价表（PT 预扣单价，基准 5s / 720p；时长线性、1080p ×2）：

| 模型 ID | 5s/720p | 10s/720p | 5s/1080p | 主要输入 |
|---|---|---|---|---|
| `wan3.0-video`（默认） | $0.20 | $0.40 | $0.40 | text, image |
| `wan2.7-t2v` | $0.475 | $0.95 | $0.95 | text, image |
| `kling-v3` | $0.42 | $0.84 | $0.84 | text, image, audio |
| `kling-v2-1-master` | $1.40 | $2.80 | $2.80 | text, image, audio（运镜） |
| `seedance-1-5-pro-251215` | $0.247 | $0.494 | $0.494 | text, image, 首尾帧, 视频+音频 ref |

换算与估算规则：
- 时长线性：5s→10s = ×2；分辨率：720p→1080p = ×2；叠加相乘。
- 视频估算走 `pt_video.py estimate -m <model> -d <秒> -r <分辨率>`，**只估不扣费**。
- 预估总价 = Σ(每镜视频估算) + 音频 / VLM（后者按实际，卡上注明不计入精确值）。
- 生成前服务端做 `pre-consume quota failed` 预扣校验，校验不过不扣费。
- 实测参考：wan3.0-video 720p 一个 6s 镜约 $0.24，8 镜约 $1.56（逐镜 estimate 求和）。

> 不同账号可用模型 / 白名单不同，以 `python pt_video.py models -t all --json` 实测为准。
> 音频与 VLM 单价 PT 未在公开 API 给出，若将来媒体模块有统一计价，再统一此处口径。

## 卡片 3 · 镜头表卡（人工卡点，必须）

**何时弹**：Step 3 `recipe_to_prompt.py` 生成 `shots.json` 后、Step 4 生成前。

**必含字段**：逐镜表格 —— 镜头号 / 时长 / 画面描述摘要 / route（`pt_generate` / `code_remake` / `reshoot`）/ 使用模型 / 单镜预估价。

**门控**：用户可改 prompt、改模型、删镜、改画幅；**确认后才生成**。这是硬性人工卡点，不得跳过（`--auto` 慎用）。

---

## 卡片 4 · 成片交付卡

**何时弹**：Step 5 合成完成、`final.mp4` 产出后。

**必含字段**：
- 成片规格：时长 / 分辨率 / 画幅 / 是否带字幕 / 音轨来源标注「全自生成」
- 本次**实际花费**：调 `pt_video.py usage` / 账单汇总，与卡片 2 预估对比
- 产物文件清单：成片 / 无字幕版 / 字幕文件 / 音轨
- 若国内发布：提醒按平台规则 + 《人工智能生成合成内容标识办法》做 AI 标注；境外发布不提示打水印

---

## 渲染注意

- 卡片承载的是决策信息，不要把完整技术日志塞进卡片；日志留在正文或产物文件里。
- 价格数字必须来自本节口径或真跑 `estimate`，禁止临时编造。
- 门控卡（1/2/3）弹出后必须**停下等用户确认**，不得自动越过进入花钱步骤。
